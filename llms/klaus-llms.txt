# Klaus (Zendesk QA)

> Klaus is an AI-powered conversation review and quality assurance platform for customer
> support teams, founded in Tallinn, Estonia in 2019 and acquired by Zendesk in 2023, where
> it ships as Zendesk QA. It samples support conversations from connected help desks, scores
> them against configurable scorecards, runs AutoQA checks, tracks disputes and calibration
> sessions, measures CSAT, and delivers coaching, quizzes and agent-performance dashboards.
> Two public REST APIs are published as Swagger 2.0 documents: a Public Import API for
> pushing conversations and users in from a custom help desk, and a Public Export API for
> pulling reviews, AutoQA ratings, CSAT, disputes, calibration sessions, scorecards, quizzes
> and users back out.

## APIs

- [Klaus Public Export API](https://pub.klausapp.com/?urls.primaryName=Public+Export+API): Export reviews, AutoQA ratings and reviews, CSAT, disputes, calibration sessions, workspace scorecards, quizzes and users. Base: `https://<subdomain>.zendesk.com/qa`.
- [Klaus Public Import API](https://pub.klausapp.com/?urls.primaryName=Public%20Import%20API): Bulk-import conversations (tickets) with comments and ticket fields, fetch or delete an imported ticket by external id, and bulk-import users. Also documented at `https://pub.klausapp.com/v1`.

## Using the API

- Authentication: bearer API token in the `Authorization` header, issued per custom
  integration under Zendesk QA > Settings > Account > Connections. You also need the
  account ID, and the workspace ID for workspace-scoped exports. There is no OAuth surface
  and therefore no scopes.
- Pagination: `page` and `pageSize` query parameters; responses carry a `pagination`
  object with `page`, `pageSize` and `total`. AutoQA exports also return `nextCursor`.
- Filtering: `fromDate` / `toDate` window most exports (`fromDate` is required on several);
  `workspace`, `connectionId`, `ratingCategoryId`, `rootCauseCode`, `revieweeExternalId`,
  `autoqaCategoryType` and `latestOnly` narrow results.
- Idempotency: import payloads carry a caller-supplied `id`. Re-sending the same id updates
  the existing conversation or comment rather than duplicating it, so imports are retry-safe.
  There is no `Idempotency-Key` header.
- Errors: the grpc-gateway `google.rpc.Status` envelope (`code`, `message`, `details`) on a
  catch-all `default` response. Not RFC 9457.
- Rate limits: 1,500 requests per minute per IP on both APIs; imports are capped at 500
  comments per ticket and 10,000 tickets per request.
